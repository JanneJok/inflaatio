# Data: sources, files and the update pipeline

Everything the site shows comes from `data/*.json` (fetched automatically) and
a few hand-maintained or semi-automatic files in `src/content/`. The build
reads these files; nothing is fetched at runtime in the browser.

- Fetch: `npm run fetch` (= `node scripts/fetch/index.js`)
- Only some sources: `npm run fetch -- --only khi,ykhi` (names: `khi`, `khi-annual`,
  `elinkustannusindeksi`, `ykhi`, `ykhi-annual`, `hyodykkeet`, `hyodykesarjat`,
  `polttoaineet`, `ansiot`, `korot`, `kalenteri`)
- Try without writing: `npm run fetch -- --dry-run`
- Other flags: `--data-dir <dir>` (write elsewhere, e.g. for experiments),
  `--no-calendar` (skip the release calendar step)
- Tests (no network): `node --test test/fetch.test.js`

No npm dependencies: Node 24 native `fetch`.

## Common conventions

- Periods: months `'YYYY-MM'`, quarters `'YYYY-Qn'`, years `'YYYY'`. Always
  ascending and contiguous inside a file (gaps are filled with `null`).
- Value arrays are aligned with their period array (same length).
- Missing value = `null`. Zero is always a real zero, never "missing".
- Rounding as published: rates 1 decimal, indices 2 decimals, prices 3
  decimals, contributions (%-yks.) 3 decimals, deposit rate 2 and Euribor 3 decimals.
- Only official published values. The only values computed by us are
  documented below (`khi.mom` before 1995-02 and `korot.depositRate`, the rate
  in force at month end). Nothing is back-calculated and presented as official.
- Files are written with `scripts/fetch/util.js#stringifyData`: objects
  indented, arrays of numbers on one line (small diffs, stable output).

## Files

### `meta.json`

```json
{
  "generatedAt": "2026-09-24T11:21:08.763Z",
  "sources": {
    "khi": { "name": "Kuluttajahintaindeksi (KHI)", "publisher": "Tilastokeskus",
             "table": "122p (vuosimuutos), 11xs (pisteluvut), 15b5 (2025=100, kuukausimuutos)",
             "url": "https://pxdata.stat.fi/…/122p.px/", "license": "CC BY 4.0",
             "updated": "2026-09-14T05:00:00Z", "latest": "2026-08" },
    "…": {}
  }
}
```

Keys: `khi, khiAnnual, elinkustannusindeksi, ykhi, ykhiAnnual, hyodykkeet,
hyodykesarjat, polttoaineet, ansiot, korot`. `table` (PxWeb) or `dataset`
(Eurostat, ECB). `updated` is the source's own timestamp of the data we hold:
the PxWeb json-stat2 `updated` field (for Tilastokeskus this is the release
time, e.g. `2026-09-14T05:00:00Z` = 14.9.2026 at 8.00), Eurostat's `updated`
(published as `2026-09-17T11:00:00+0200`; stored as strict ISO 8601
`2026-09-17T11:00:00+02:00` by `isoTimestamp()` in `scripts/fetch/index.js`, so
every `Date` parser accepts it), or the ECB `Last-Modified` header. `latest` is
the newest period with data. `generatedAt` changes only when a data file or a
meta entry changed.

### `khi.json` — kuluttajahintaindeksi, monthly

```
{ months: ['1972-01' … '2026-08'],
  yoy:   annual change %, 122p (null before 1980-01),
  mom:   monthly change %,
  momOfficialFrom: '1995-02',
  index: { '2025=100': [], '2015=100': [], '2010=100': [], '2005=100': [], '2000=100': [],
           '1995=100': [], '1990=100': [], '1985=100': [], '1981=100': [], '1977=100': [], '1972=100': [] } }
```

- `index['<base>']` = the official point figure series of that base from 11xs.
  Each base starts in its base year (e.g. `'2015=100'` is `null` before
  2015-01, `'1972=100'` covers everything). Pick an older base for older
  months — never chain a newer base backwards yourself.
- `index['2025=100']` from 2025-01 is 11xs; before that (1995-01 →) it is the
  total index of table 15b5, which Tilastokeskus publishes chained to
  2025=100. The fetcher checks that both agree where they overlap.
- `mom` is the official monthly change of 15b5 (`km_khi`, total) from
  `momOfficialFrom` on. Before that month (1972–1995-01) it is computed from
  the official 1972=100 index and rounded to one decimal — label it as
  calculated if it is ever shown.
- "Muutos edellisestä kuukaudesta" in the UI is the difference of two `yoy`
  values (%-yks.), not `mom`.

### `khi-annual.json` — official annual figures (complete years only)

```
{ years: ['1972' … '2025'], yoy: 122q official annual change % (null before 1980),
  index: { '2015=100': [], …, '1972=100': [] } }   // 11xt annual averages
```

The current partial year is not in this file; pages compute it from
`khi.json` (mean of the available monthly `yoy` values) and label it with the
month span, e.g. "2026 (tammi–elo)". 11xt has no 2025=100 series.

### `elinkustannusindeksi.json`

```
{ monthly:     { base: '1951:10=100', months: ['1951-10' …], values: [] },   // 11xl
  annual:      { base: '1951:10=100', years: ['1952' …], values: [] },       // 11xm
  monthly1939: { base: '1938:8–1939:7=100', months: ['1939-08' …], values: [] }, // 11xn
  annual1914:  { base: '1914:1–6=100', years: ['1860' …], values: [] } }     // 11xy
```

`monthly` is the series most rent and index clauses refer to (8/2026 = 2385).
`monthly1939` and `annual1914` allow value-of-money calculations before 1951
(markka conversions and the 1963 currency reform are the calculator's job).

### `ykhi.json` — Eurostat HICP, monthly

```
{ months: ['1996-01' … '2026-08'],
  geo: {
    FI: { yoy, mom, index: { '2025=100': [], '2015=100': [] }, coreYoy },
    EA: { yoy, mom, index: { … }, coreYoy },
    SE: { yoy }, DK: { yoy }, NO: { yoy }, DE: { yoy }, EE: { yoy }, EU: { yoy } },
  labels: { FI: 'Suomi', EA: 'Euroalue', SE: 'Ruotsi', DK: 'Tanska', NO: 'Norja', DE: 'Saksa', EE: 'Viro', EU: 'EU' },
  flags: { FI: { '2026-09': 'p' } },
  countries: { months: [25 latest months], yoy: { AT: [], BE: [], … 27 EU states }, labels: { AT: 'Itävalta', … } } }
```

- `yoy` = RCH_A (starts 1997-01), `mom` = RCH_M, `index` = I25 / I15,
  `coreYoy` = TOT_X_NRG_FOOD RCH_A ("pohjainflaatio": HICP excluding energy,
  food, alcohol and tobacco; starts 2000-12).
- `EA` = Eurostat geo `EA`, the euro area with changing composition (EA21 from
  2026). `EU` = `EU27_2020`.
- `flags[geo][month]`: `'p'` = ennakko (flash estimate). Set when Eurostat
  flags the value `p` or `e` (flash rates are marked estimated), and for FI/EA
  whenever the annual rate exists but the index is not published yet — that
  is exactly the state between Eurostat's flash (end of the month) and the
  full release (~17th of the next month). Other Eurostat flags are copied as
  they are. An empty `flags` object means every value is final.
- `countries` holds the EU27 member states for rankings ("Suomi sijalla N/27").

### `ykhi-annual.json`

```
{ years: ['1997' … '2025'], geo: { FI: [], EA: [], SE: [], DK: [], NO: [], DE: [], EE: [], EU: [] }, labels }
```

Official annual average rate of change (RCH_A_AVG). E.g. FI 2000 = 3.0,
2023 = 4.3 (the monthly mean would give 2.9 and 4.4).

### `hyodykkeet.json` — what drives inflation

```
{ latest: '2026-08', base: '2025=100', weightYear: '2026',
  items: [ { code: '011221', coicop: '01.1.2.2.1', name: 'Naudanliha tuore, jäähdytetty tai jäädytetty',
             shortName?, nature: 'LI'|'PKS'|'KS'|'P'|null, level: 5, parent: '01122', leaf: true,
             weight: ‰ or null, index, yoy, mom, contribution, contributionMom, slug? } … 390 ],
  groups: { months: [60 latest], codes: ['SSS','01',…,'13'],
            series: { SSS: { yoy: [], contribution: [] }, '01': {…}, … '13': {…} } } }
```

- `code` = PxWeb code (COICOP without dots, `SSS` = total), `coicop` = dotted code.
- `level`: 0 total, 1 main group ('07'), 2 ('07.2'), … 5.
- `shortName`: everyday Finnish name for the 13 main groups (e.g. '04' →
  "Asuminen ja energia"); `name` is the official label in sentence case.
- `nature`: COICOP 2018 durability marker from the label: LI lyhytikäinen
  (non-durable), PKS puolikestävä, KS kestävä, P palvelu.
- `weight` (‰) from 15bc for `weightYear`; `null` for detailed items that
  have no published weight.
- `contribution` = "vaikutus vuodessa" (%-yks.), `contributionMom` =
  "vaikutus kuukaudessa". The main-group contributions sum to the total
  (≈ `yoy` of `SSS`). Tilastokeskus publishes contributions only from
  2026-01 (the COICOP 2018 / 2025=100 tables); in `groups.series.*.contribution`
  every earlier month is `null`. Pages must not back-calculate them: before
  2026-01 show each group's own annual change instead.
- `leaf` = no sub-items. For top/bottom lists use leaves (otherwise a group
  and its single identical sub-item both appear) and consider filtering by the
  parent's weight, as detailed items have no weight of their own.
- `groups.codes` gives the display order; don't rely on object key order
  (keys '10'–'13' sort first in JavaScript).
- `slug` links the item to `/hinnat/<slug>/` when it is in `hyodykesivut.json`.

### `hyodykesarjat.json` — commodity pages

```
{ latest, base: '2025=100',
  items: { '<slug>': { code, coicop, name, officialName, category, months, yoy, index } } }
```

One entry per row of `scripts/fetch/hyodykesivut.json` (`[{ slug, code, name,
category }]`, 62 recognisable items; `name` is the page name, `officialName`
the Tilastokeskus label). Each item's `months` run from its first published
value (mostly 2015-01 for the chained COICOP 2018 series) to the latest month.
Values are index changes, not euro prices (euro prices exist only for fuels).
To add or change a page, edit `hyodykesivut.json` (codes must exist in 15b5;
the fetch warns about unknown codes) and run `npm run fetch -- --only hyodykkeet,hyodykesarjat`.

### `polttoaineet.json`

```
{ months: ['2002-01' …], unit: '€/l',
  series: { bensiini95: [], bensiini98: [], diesel: [], polttooljy: [] },
  labels: { bensiini95: 'Bensiini 95 E 10', bensiini98: 'Bensiini 98 E 5', diesel: 'Diesel', polttooljy: 'Kevyt polttoöljy' } }
```

Monthly average consumer prices (not the pump price of a single day). The
biogas series of 11xx (€/kg) are left out. Tilastokeskus publishes the month
at the end of the same month (e.g. August on 31.8.).

### `ansiot.json`

```
{ periods: ['1996-Q1' … '2026-Q2'], freq: 'Q',
  nominalYoy, realYoy,                 // % change from the same quarter a year earlier
  indexBase: '2015=100', nominalIndex, realIndex,
  preliminary: ['2025-Q1', …] }        // quarters Tilastokeskus marks with '*' (ennakkotieto)
```

### `korot.json`

```
{ months: ['1999-01' …], depositRate: [], euribor12: [],
  decisions: [ { date: '2026-09-16', depositRate: 2.5 } … ] }
```

- `decisions[].date` is the date the rate took effect (ECB change dates),
  not the Governing Council decision date (that is a few days earlier). The
  first row (1999-01-01) is the starting level.
- `depositRate[m]` = rate in force on the last day of month m (derived from
  `decisions`). Months run to the last complete month, so a change on
  16.9.2026 shows in `depositRate` from 2026-09 on once September is over;
  use `decisions.at(-1)` for "the rate now".
- `euribor12` = monthly average of the daily 12-month Euribor (3 decimals).

### `muutosloki.json`

`[ { date: 'YYYY-MM-DD', source: 'khi'|'ykhi'|'ansiot'|'korot', period, kind?: 'ennakko'|'lopullinen', text } ]`,
newest first, max 300 entries. See [below](#release-calendar-and-changelog).

## Pipeline rules

`scripts/fetch/index.js`:

1. Load the previous `data/*.json`, `meta.json` and `muutosloki.json`.
2. Run every source module in parallel with `Promise.allSettled`. PxWeb calls
   share one rate limiter (30 calls / 60 s, 2 in flight; the API allows 40 /
   60 s and 120 000 cells per query — larger queries are split automatically).
   Every HTTP request has a 30 s timeout and 3 retries with exponential backoff
   for 429/5xx/network errors (`scripts/fetch/http.js`).
3. Validate each result against the rules below and against the previous file.
4. A source that failed to fetch or validate keeps its previous file untouched
   (the site keeps showing the last good data) and marks the run failed.
5. A data file is written only when its content changed (formatting and
   timestamps are ignored). Writes go through a temp file + rename.
6. `meta.json`: the entry of a source is refreshed when its data changed;
   `generatedAt` is set only when something changed. So a daily run on a day
   without new data changes nothing and produces no commit.
7. `muutosloki.json`: entries are added when a source publishes a new period
   (see below).
8. `src/content/julkaisukalenteri.json` is refreshed from the official release
   calendars (best effort — failures are warnings only).
9. Summary to stdout; if `GITHUB_STEP_SUMMARY` is set, a Markdown table is
   appended there too.
10. Exit code 1 if any source failed (fetch or validation) or KHI/YKHI is
    stale; 0 otherwise. Successful sources are written before exiting, so the
    workflow should commit `data/` and `src/content/julkaisukalenteri.json`
    even when the fetch step fails (e.g. `if: always()` on the commit step,
    then fail the job so GitHub notifies the owner).

Workflow notes for `.github/workflows/update-data.yml`: run daily (and a few
times on release mornings; Tilastokeskus publishes at 8.00 Finnish time,
Eurostat at 12.00), `timeout-minutes: 10`, `concurrency: data-update`, commit
only if `git status --porcelain data src/content/julkaisukalenteri.json` is
non-empty, `git pull --rebase` before push. A typical run takes a few seconds.

## Validation

Two layers:

- `test/data-contract.test.js` (part of `npm test`) checks the committed files
  against the structural contract of this document and SPEC §7: period format
  and contiguity, aligned arrays, `null` for missing, rounding, required keys,
  strict ISO timestamps in `meta.json`, `meta.latest` vs. the files, slugs vs.
  `hyodykesivut.json`, and the release calendar shape. It runs on every pull
  request, so a fetcher change that breaks what the pages consume fails CI.
- At fetch time, `scripts/fetch/validate.js` plus a `validate(data, prev)` per source:

- periods well-formed, strictly ascending, contiguous;
- arrays aligned with periods; values finite numbers or `null`;
- ranges: annual rates −5…30 % (KHI, YKHI), monthly −5…10 %, commodity items
  −90…500 %, indices and prices > 0 (fuel 0.2…6 €/l), wages −10…25 %, rates −2…15 %;
- no zero-as-missing: an index of 0 fails, and a rate of exactly 0 where the
  paired index is missing fails;
- consistency: KHI `yoy` vs `index['2025=100']` and YKHI `yoy` vs I25 within
  0.15 %-yks. (computed from the rounded indices);
- KHI: latest `yoy` month = latest index month; 2025=100 and 2015=100 present;
- YKHI: a FI month with a rate but no index must be flagged `'p'`;
- commodity groups: main-group weights sum to 1000 ‰ and contributions to the
  total annual change (±0.3);
- the latest period never moves backwards compared with the previous file;
- freshness: the latest KHI and YKHI month may be at most 75 days old,
  measured from the 15th of that month (normal maximum is ~62 days, just
  before the next KHI release). A stale source fails the run (status `stale`)
  even if its fetch "succeeded" — this catches silently frozen sources.

## Release calendar and changelog

### `src/content/julkaisukalenteri.json`

`[ { date, time, source: 'khi'|'ykhi-ennakko'|'ykhi', period, label, publisher, url } ]`,
sorted by date; `time` is Finnish time. Maintained by `scripts/fetch/kalenteri.js`
from the official calendars only:

- Tilastokeskus: the KHI statistic page <https://stat.fi/fi/tilasto/khi>
  embeds the next ~2 months of planned releases ("Kuluttajahintaindeksi 2026,
  syyskuu", "Yhdenmukaistettu kuluttajahintaindeksi 2026, syyskuu, ennakko").
  The page is parsed (best effort; if the layout changes the run prints a
  warning and keeps the file).
- Eurostat: the euro-indicator release calendar
  (<https://ec.europa.eu/eurostat/news/release-calendar>, JSON behind it):
  "Flash estimate inflation euro area" → `ykhi-ennakko` (includes Finland's
  flash) and "Inflation (HICP)" → `ykhi`. Eurostat publishes the calendar per
  calendar year; its times are Luxembourg time (11.00 = 12.00 in Finland).

One entry per (source, period); Eurostat wins for YKHI (our YKHI data is
Eurostat's), Tilastokeskus for KHI. Entries older than 60 days are pruned.
Dates appear as soon as the publishers announce them, so the file usually
covers 2–3 months ahead for KHI and until the end of the calendar year for
Eurostat. To add a date manually, add an entry with the same shape (only
officially announced dates).

### `data/muutosloki.json`

Generated when the latest period of a source changes:

- `khi`: "Tilastokeskus julkaisi elokuun 2026 kuluttajahintaindeksin: inflaatio 2,2 % (heinäkuussa 2,1 %)."
- `ykhi`, `kind: 'ennakko'`: "Eurostat julkaisi elokuun 2026 YKHI-ennakon: Suomi 2,4 %, euroalue 3,3 %."
- `ykhi`, `kind: 'lopullinen'` (flash became final, same month): "Eurostat julkaisi heinäkuun 2026 lopulliset YKHI-luvut: Suomi 2,5 % (ennakko 2,6 %), euroalue 2,9 %."
- `ansiot`: "Tilastokeskus julkaisi ansiotasoindeksin 2. neljännekseltä 2026: ansiot +3,4 %, reaaliansiot +1,6 % vuodessa."
- `korot` (new ECB rate change): "EKP:n talletuskorko 2,50 % 16.9.2026 alkaen (aiemmin 2,25 %)."

`date` is the source's own release timestamp when it is recent (≤ 10 days),
otherwise the run date. Duplicates (same source, period, kind) are ignored.
Texts are built with `src/js/lib/format.js`. The file was seeded with the
March–August 2026 releases (see the verification record).

## How to add a source

1. Explore the API: list the PxWeb folder (`GET https://pxdata.stat.fi/PxWeb/api/v1/fi/StatFin/<db>/`),
   read the table metadata (`GET …/<table>.px`) and try a small query; for
   Eurostat add `lastTimePeriod=1` and read the dimension ids and codes.
2. Create `scripts/fetch/sources/<file>.js` exporting a default object:
   `{ key, file, name, publisher, license, fetch({ log, today }) → { data, meta: { table|dataset, url, updated, latest } }, validate(data, prev), latest(data), events?(data, prev), freshness? }`.
   Resolve tables with `resolveTable(db, { id, title })` (id first, title
   pattern as fallback) and pick variables/values with `findVariable` /
   `findValue` by code or label pattern — never by position.
3. Follow the conventions above (contiguous periods, `null` for missing,
   rounding, official values only) and write a `validate` with sensible ranges.
4. Register the module in `SOURCES` in `scripts/fetch/index.js` and add the key
   to the table in this document.
5. Add fixtures and tests to `test/fetch.test.js` (no network in tests).
6. Run `npm run fetch -- --only <file> --dry-run`, then without `--dry-run`.

## Known caveats

- **Base year 2025=100 (2026).** Tilastokeskus moved KHI to 2025=100 and to the
  COICOP 2018 classification with the January 2026 figures; Eurostat moved the
  HICP to ECOICOP ver.2 (new dataset `prc_hicp_minr`, dimension `coicop18`,
  unit `I25`; the old `prc_hicp_manr`/`midx` are frozen at 2025-12). The site
  shows 2025=100 by default; 2015=100 and older bases stay available because
  contracts refer to them. Commodity series (15b5) are chained by Tilastokeskus
  to the new classification; detailed items mostly start in 2015.
- **Table/variable renames.** In 2026 PxWeb switched to short table ids
  (`122p.px` instead of `statfin_khi_pxt_122p.px`) and codes `timeperiod_m` /
  `contentscode`. The fetchers discover tables and codes at run time; if an id
  disappears they fall back to a title pattern and log a warning. If a
  Eurostat dataset is retired, the fetcher searches Eurostat's table of
  contents for a successor with the same title pattern.
- **Provisional values.** YKHI flash values (`flags … 'p'`) change at the full
  release (e.g. FI May 2026: flash 3,0 %, final 2,8 %). Label them "ennakko".
  Ansiotasoindeksi quarters in `preliminary` are revised later. KHI itself is
  not revised after publication.
- **KHI vs YKHI.** Different baskets (KHI includes owner-occupied housing
  costs and interest), so the rates differ; compare like with like.
- **Partial current year.** Never mix it with the official annual figures
  without labelling the month span.
- **Weights.** 15bc gives weights for the current year only (`weightYear`).
  Early in a year the latest month and the weights can briefly refer to
  different years; check `weightYear` against `latest`.
- **Eurostat `updated`** changes on every Eurostat release (any country), so it
  is only stored when our data changed.
- **Release calendar scraping** of stat.fi depends on the page embedding the
  publications; if it breaks the run warns and keeps the file (the data fetch
  is unaffected). Eurostat's calendar JSON is an internal endpoint of their
  website.
